# Установка и проверка

Всё, что ниже, делается **на живых устройствах** — ни эмулятор, ни тесты это не заменяют.
Порядок важен: сервер → браслет → телефон, потому что каждый следующий шаг проверяется
предыдущим.

Заведите под рукой `docs/DECISIONS.md` — в конце есть чек-лист вопросов, ответы на
которые надо туда записать.

---

## 0. Что понадобится

| | |
|---|---|
| Сервер | Dell OptiPlex с Docker, домен, который вы привяжете сами |
| Android | AstroBox 2.1.0 с [astrobox.online](https://astrobox.online) |
| iPhone | AstroBox из App Store, **iOS 16.5+** (лучше 26.5+) |
| Браслет | Xiaomi Smart Band 10, заряжен |

Если на телефоне стоял AstroBox v1 — **удалите его перед установкой v2**, иначе будут
проблемы (прямое указание разработчиков).

## 1. Сервер на OptiPlex

```bash
git clone git@github.com:ThNikGhost/omsu-band-schedule.git && cd omsu-band-schedule
```

Токены — по одному на человека, чтобы отзывались независимо:

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(32))"
```

Создайте `server/.env` на основе `server/.env.example`. Минимум: `GROUPS=5028`,
`API_TOKENS=<токен1>,<токен2>`. Каталог данных должен принадлежать пользователю
контейнера:

```bash
mkdir -p data && sudo chown 1000:1000 data
```

```bash
docker compose up -d --build
```

Через минуту-две первая синхронизация завершится:

```bash
curl -s http://localhost:8080/health | python3 -m json.tool
```

Ждём `"status": "ok"` и `"has_snapshot": true`. Если `"degraded"` — смотрите
`last_error`; апстрим ОмГУ периодически отваливается, сервер это переживает и
повторит с задержкой.

Проверьте расписание своим токеном:

```bash
curl -s -H "Authorization: Bearer $TOKEN" "http://localhost:8080/api/v1/schedule?group=5028&days=14&subgroup=1" | python3 -m json.tool | head -30
```

Дальше привяжите домен к порту 8080 своим обратным прокси — **сервер должен быть доступен
по HTTPS снаружи**, иначе плагин на телефоне до него не достучится. Проверьте с телефона,
открыв в браузере `https://ваш-домен/health`.

> Не поднимайте несколько воркеров uvicorn: снапшоты, rate limiter и планировщик живут
> в памяти процесса, второй воркер — это второй планировщик.

## 2. Собрать артефакты

Оба уже собраны и лежат в репозитории после сборки; если нужно пересобрать:

```bash
cd band-app && npm install && npm run gen && npm run build
```
→ `band-app/dist/ru.omsu.bandschedule.debug.1.0.0.rpk` (~28 КБ)

Для плагина нужен **Rust с таргетом `wasm32-wasip2`** на той машине, где собираете.
Если его там нет, `build_dist.py` падает с `FileNotFoundError: 'cargo'`:

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y --profile minimal
```

```bash
source "$HOME/.cargo/env" && rustup target add wasm32-wasip2
```

```bash
cd astrobox-plugin && python3 scripts/build_dist.py --release --package
```
→ `astrobox-plugin/dist/Расписание ОмГУ.abp` (~178 КБ)

**Собирать плагин на сервере не обязательно** — это файл для телефона, серверу он не
нужен. Если не хотите ставить полтора гигабайта тулчейна на NAS, соберите его на рабочей
машине и скопируйте `.abp` на телефон напрямую.

На Windows плагин собирается **только в WSL** — Smart App Control блокирует `cargo.exe`
(см. `docs/DECISIONS.md`).

> `npm install` в `band-app` ругается на уязвимости в зависимостях — это дерево
> `aiot-toolkit` (старые eslint и glob). Оно участвует только в сборке и в `.rpk` не
> попадает; трогать `npm audit fix` не нужно, он сломает тулчейн.

## 3. Android

### 3.1 Подключить браслет к AstroBox

AstroBox попросит **AuthKey** — ключ сопряжения. Искать его вручную не нужно: официальный
путь по документации — войти в Mi-аккаунт, тогда ключ подтянется сам.

**Шаг 1. Импортировать устройства из Mi-аккаунта.**
Список устройств (на телефоне — капсула внизу, затем кнопка переключения устройств вверху
экрана) → кнопка импорта → вход в Mi-аккаунт (Mi ID, телефон или почта) → двухфакторка,
если попросит.

Аккаунт должен быть **тот же**, к которому привязан браслет, иначе в списке его не будет.

> Если Android-сборка вылетает при входе в Mi-аккаунт — это известная проблема варианта
> **без встроенного WebView**. Скачайте на странице загрузки версию **«Android (с WebView)»**.

**Шаг 2. Перевести браслет в режим подключения.** Нужен при любом способе:
Настройки → «Мои устройства» (страница с перезагрузкой и выключением) → **«Подключить
новый телефон»** → синяя галочка справа внизу. Браслет перейдёт в режим ожидания.

**Шаг 3.** Вернуться в AstroBox и нажать на устройство в списке. Браслет завибрирует —
подтвердите синей галочкой. На телефоне появится запрос сопряжения (на Android может
прийти уведомлением) — подтвердите.

**Если Mi-аккаунт не вариант.** У команды AstroBox есть официальный плагин
**«AuthKey提取工具»** — достаёт имя устройства и AuthKey из логов или базы Mi Fitness.
Ставится как наш: страница плагинов → «+». Просит одно разрешение, `clipboard.write`.
Нужен установленный Mi Fitness с подключённым браслетом на том же телефоне.
Затем ключ вводится вручную при подключении устройства.

> **Про Mi Fitness.** Официальной информации о совместной работе нет. Архитектурно
> конфликта быть не должно — у браслета несколько слотов телефонов, — но сообщество
> сообщает о разрывах при одновременной активности. Если начнутся отвалы: отключите
> у одного из приложений разрешение «Устройства поблизости» и подключитесь заново.
> **Запишите, что получилось, в `DECISIONS.md`** — это открытый вопрос.

### 3.2 Установить приложение на браслет

AstroBox → страница устройства → карточка быстрых приложений → **«+»** справа вверху →
выбрать `.rpk`.

Если автоустановка выключена, зайдите в очередь и нажмите «Начать».

**Проверьте на браслете:**

- [ ] Приложение появилось в списке. **Как отображается название?** Документация Vela
      ограничивает `name` шестью иероглифами, а «Расписание» — десять символов. Если
      обрезалось — скажите, поменяю на «ОмГУ».
- [ ] Открывается и показывает **«Нет расписания · Откройте AstroBox»** — это правильно,
      данных ещё нет.
- [ ] Тап по экрану листает разделы, внизу видны точки-индикаторы.

### 3.3 Установить плагин

AstroBox → страница плагинов → **«+»** справа вверху → выбрать `.abp`. AstroBox попросит
перезапуск, потом спросит разрешения — нужны все пять: `network`, `device`,
`interconnect`, `register_interconnect_recv`, `thirdpartyapp`.

Откройте плагин и заполните:

| Поле | Что вписать |
|---|---|
| Адрес сервера | `https://ваш-домен` (без слеша в конце) |
| Токен | ваш токен из `.env` |
| Группа | `5028` |
| Подгруппа | `1` или `2` — **здесь вы с девушкой расходитесь**; пусто = все пары |
| Дней вперёд | `14` |
| Приложение на браслете | `ru.omsu.bandschedule` |

«Сохранить», затем **«Синхронизировать»**.

В журнале плагина должно появиться примерно так:

```
запрос: https://ваш-домен/api/v1/schedule?group=5028&days=14&subgroup=1
получено: 9 дн., 20 пар, хэш 70bbe23f4e25
одно сообщение — 4372 байт, кадров: 1
приложение на браслете запущено
браслет подтвердил приём, хэш 70bbe23f4e25
```

**Ключевая строка — последняя.** Если «браслет подтвердил приём» нет, значит `done`
не дошёл: смотрите раздел «Если не работает».

### 3.4 Проверить на браслете

- [ ] Экран «Сейчас» показывает текущее состояние: идёт пара / перемена / пары закончились
- [ ] «Сегодня» — список пар, текущая ярче, прошедшие приглушены
- [ ] «Далее» — следующий учебный день, список **прокручивается**, если пар больше пяти
- [ ] «Звонки» — таблица, текущая пара подсвечена, большой перерыв на месте между 2 и 3
- [ ] «Состояние» — группа `МБС-301-О-01`, время обновления, «телефон на связи»
- [ ] **Символ `…`** в сокращённых названиях рисуется, а не показывается квадратом
- [ ] Кегль читаемый (12–15 px на 1.72″)
- [ ] Тап по кнопке «Обновить» — что происходит? Синхронизация, или ещё и переход на
      «Сейчас»? Оба варианта нормальны, но **запишите, какой**
- [ ] Долгое нажатие на экране запускает синхронизацию

### 3.5 Главная проверка: офлайн

Ради этого всё и делалось.

1. Выключите на телефоне интернет **и** Bluetooth
2. Откройте приложение на браслете

- [ ] Расписание на месте, все экраны работают
- [ ] На «Состояние» — «телефон недоступен»
- [ ] Через сутки без синхронизации появляется пометка «данные устарели»

## 4. iPhone

Те же шаги 3.1–3.5, с поправками:

- AstroBox ставится **из App Store**, минимум iOS 16.5
- Версия на iOS отстаёт (2.0.2 против 2.1.0) — это нормально
- При ошибке **`TargetRejected`**: системные Настройки → Bluetooth → «забыть» браслет →
  подключиться заново
- Подгруппу поставьте **другую**, чем на первом телефоне
- На iOS WASM исполняется интерпретатором, без JIT — синхронизация может идти заметно
  дольше. Если разница большая, **запишите, насколько**

> **Фон на iOS.** Приложения там не живут в фоне, и официального описания, держит ли
> AstroBox BLE-сессию в фоне, нет. Практически: синхронизация происходит, когда AstroBox
> открыт. Именно поэтому браслет обязан работать офлайн — и именно это проверяет шаг 3.5.

## 5. Запасной путь без плагина

Если с плагином не сложится, расписание можно подписать в календарь телефона:

```
https://ваш-домен/api/v1/calendar/5028.ics?token=<токен>&subgroup=1
```

iPhone: Настройки → Календарь → Учётные записи → Добавить → Другое → Подписной календарь.

- [ ] События появились, время совпадает с расписанием звонков
- [ ] **Показывает ли Mi Fitness эти события на браслете?** Открытый вопрос — проверьте
      и запишите

## Если не работает

| Симптом | Что смотреть |
|---|---|
| Плагин: «сервер недоступен» | Откройте `https://ваш-домен/health` в браузере телефона. Скорее всего дело в прокси или сертификате |
| Плагин: «сервер не принял токен» | Токен в плагине не совпадает с `API_TOKENS` в `.env`. Пробел в конце тоже считается |
| Плагин: «сервер ещё не загрузил расписание» | Сервер жив, но снапшота нет. `curl /health` → смотрите `last_error` |
| Плагин: «браслет не подключён» | Браслет не виден AstroBox. Переподключите; на iOS — «забыть» устройство в Bluetooth |
| «приложение не установлено на браслете» | Package name в настройках плагина ≠ `ru.omsu.bandschedule` |
| Отправил, но `done` не пришёл | Приложение на браслете не успело запуститься. Откройте его вручную и нажмите «Синхронизировать» ещё раз. Если помогает — **скажите, увеличу задержку** (сейчас 2 с) |
| Браслет: «данные отклонены» | Расхождение версий сервера и приложения. Соберите `.rpk` заново |
| Браслет: «передача оборвалась» | Связь пропала на середине. Старый кэш цел, просто повторите |

Логи сервера:

```bash
docker compose logs -f --tail 50
```

Токены в них замаскированы — лог можно показывать, не вычищая.

## Что записать в `DECISIONS.md`

Эти вопросы висят открытыми с фаз 2–4, и закрыть их может только живая проверка:

- [ ] Как отображается название «Расписание» в списке приложений
- [ ] Рисует ли шрифт браслета символ `…`
- [ ] Масштаб `designWidth: "device-width"` — 1:1 или нет
- [ ] Прокрутка `<list>` на дне с шестью и более парами
- [ ] Доходит ли тап по кнопке до обработчика страницы
- [ ] Хватает ли 2 с после запуска приложения на браслете
- [ ] Уживаются ли AstroBox и Mi Fitness на одном телефоне
- [ ] Держит ли AstroBox связь в фоне на iOS
- [ ] Показывает ли Mi Fitness события подписного ICS на браслете
- [ ] Реальный лимит размера одного сообщения interconnect (у нас 4372 байта проходят —
      если захотите нащупать потолок, это отдельный эксперимент)
