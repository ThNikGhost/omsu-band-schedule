# band-app — приложение для Xiaomi Smart Band 10

Vela quick app, package `ru.omsu.bandschedule`, экран 212×520.

Расписание приходит с телефона по `@system.interconnect` от плагина AstroBox и
лежит в `@system.storage`. Приложение полностью работает офлайн: без телефона
показывается последний кэш, а если кэша нет — экран «Откройте AstroBox».

## Устройство

Вся логика лежит в `src/common/*.js` и **не импортирует ни одного `@system.*`**. Это
сделано намеренно: эмулятор Vela тяжёлый, на устройстве не отладишься, а так весь расчёт
состояний проверяется обычными тестами на Node. Компонент страницы только раскладывает готовые
строки по элементам.

| Файл | Ответственность |
|---|---|
| `common/clock.js` | что происходит сейчас: идёт пара, перемена, большой перерыв, пары кончились |
| `common/viewmodel.js` | готовые строки для каждого экрана |
| `common/schedule.js` | чтение кэша, поиск дня, «данные устарели» |
| `common/format.js` | время, даты, русские склонения. Без `Intl` — его на Vela может не быть |
| `common/link.js` | протокол с телефоном: разбор, сборка из частей, проверка целостности |
| `common/bells.js`, `common/mock.js` | **генерируются** из `shared/` командой `npm run gen` |
| `device/link.js`, `device/storage.js` | тонкие обёртки над `@system.*` — единственное место, где они встречаются |
| `pages/index/index.ux` | единственная страница: шесть экранов, переключение по тапу |

Перемены считаются по **парам студента**, а не по сетке звонков: у человека с 1-й и 4-й парой
между ними не «перемена», а окно, и ему важно, когда начнётся 4-я.

## Связь с телефоном

Тап по экрану — следующий раздел, **долгое нажатие — запросить расписание**. Запрос
уходит и сам при каждом открытии приложения: если ничего не изменилось, телефон
отвечает `up_to_date`, и по BLE не едет ничего.

Целостность собранных данных проверяется **без хэширования на браслете**: расписание
несёт собственное поле `h`, поэтому битая сборка либо не разбирается как JSON, либо
расходится с хэшем из `sync_begin`. Это ловит потерю, дубль и перестановку частей —
то, что реально случается. Проверкой подлинности это не является, её обеспечивают
сопряжение по BLE и сам плагин.

Запись в кэш идёт через временный ключ с чтением обратно: устройство без свободного
места обрезает запись молча, и только повторное чтение это ловит. Пока новые данные
не подтверждены, показывается старый кэш.

Совместимость с плагином проверяется отдельно: `test/cross-protocol.test.js` скармливает
приёмнику кадры, сгенерированные **настоящим Rust-кодом** плагина
(`test/data/plugin-frames.json`). Обновить фикстуру:

```bash
cd ../astrobox-plugin && cargo run -p omsu-sync-core --example emit_frames --target x86_64-unknown-linux-gnu
```

## Команды

```bash
npm install && npm run gen
```

```bash
npm test
```

```bash
npm run build
```

Собранный пакет — `dist/ru.omsu.bandschedule.debug.<версия>.rpk` (около 50 КБ, подписан
отладочным ключом из состава тулкита). `npm run build` идёт через `scripts/build.mjs`:
сам `aiot build` глотает исключения и выходит с кодом 0, поэтому обёртка проверяет,
что пакет действительно пересобран и в нём нет смешения модульных систем.

## Превью без эмулятора

```bash
npx http-server preview -p 8123
```

Затем открыть `http://127.0.0.1:8123/` (или любым другим статическим сервером из корня
`band-app`, тогда `http://127.0.0.1:8123/preview/`).

Страница рисует содержательные экраны в рамке 212×520, используя **те же модули** `src/common/*.js`
и те же размеры, что `index.ux`. Экран «нет расписания» в превью не показан — он появляется
только когда кэш пуст. Есть ползунок времени и кнопки состояний: идёт пара, перерыв
внутри пары, большой перерыв, после пар, день без пар. Экран, в который содержимое не влезло,
обводится красным.

Это **приближение**, а не эмулятор: шрифт и метрики строк на браслете свои, а перенос
текста посимвольный. Итоговый вид проверяется только на устройстве — эмулятор Vela мы
так и не ставили, и до сих пор обходились без него.

## Этапы возвращения на браслет

Первая версия приложения дала чёрный экран и подвесила браслет целиком. Поэтому приложение
ставится обратно **по одной возможности за раз**, и единственное, что меняется между этими
сборками, — константа `STAGE` в [`src/device/stage.js`](src/device/stage.js):

| `STAGE` | Что доступно | Что проверяем |
|---|---|---|
| `1` | только отрисовка, ни один `@system.*` не резолвится | видно ли текст, листаются ли экраны |
| `2` | `+ @system.storage` | переживает ли кэш перезапуск |
| `3` | `+ @system.interconnect` | идёт ли синхронизация, какой предельный размер кадра |

`require('@system.*')` намеренно ленивый, внутри обёрток в `src/device/`: на непройденном
этапе модуль не резолвится вообще. При этом `manifest.features` перечисляет все три модуля
всегда — тулчейн падает, если использованный модуль не объявлен.

Пока шли этапы, фон страницы был выкрашен в заметный цвет: при чёрном фоне упавший рендер
и корректный рендер выглядят одинаково, и именно поэтому причину так долго не могли найти.
Приём стоит повторять при любой новой проблеме с отрисовкой. Поле
`display.backgroundColor` для этого **не годится** — оно перекрывает фон страницы,
цвет надо ставить в CSS корневого `div`.

**Шестой экран «Отладка»** показывает сборку, состояние связи, счётчики кадров, размер
крупнейшего принятого кадра, объём кэша и последнюю ошибку. Он нужен потому, что снять
`console.log` с браслета нечем: ни AstroBox, ни его CLI этого не умеют.

Правила платформы, которым подчиняется весь `band-app/`, — в [`docs/VELA-RULES.md`](../docs/VELA-RULES.md).
Читать перед правкой: компилятор эти нарушения не ловит.

## Проверено на устройстве

Всё ниже проверено на живом Band 10 16.09.2026 — до этого раздел назывался «что ещё
не проверено», и почти каждый пункт в нём при встрече с железом оказался не таким,
как ожидалось. Платформенные выводы вынесены в [`docs/VELA-RULES.md`](../docs/VELA-RULES.md).

| Что | Чем кончилось |
|---|---|
| Рендер вообще | Работает, но только после того, как из `package.json` убрали `"type": "module"` — иначе страница умирала до отрисовки |
| `<list>` / `<list-item>` | **Не рисует ничего**, хотя место занимает. Строки — обычные `div` с `for` |
| Прокрутка | `<scroll scroll-y="true">` с фиксированной высотой. Без атрибута компонент рисует детей и стоит на месте |
| `designWidth: 212` | Верно, масштаб 1:1 |
| Название «ОмГУ» | Помещается |
| Символ `…` | Рисуется. А вот `✕` выводится пустым квадратом |
| Всплытие тапа | Тап по кнопке доходит до обработчика страницы; оба исхода оказались приемлемыми, как и закладывалось |
| `send({data})` | Объект — верно, сообщение уходит |
| Размер сообщения | **4288 байт проходят одним кадром**, нарезка не понадобилась |
| `@system.storage` | Пишет и читает; кэш переживает перезапуск приложения |
| Читаемость | Кегли 12–15 px оказались нечитаемыми. Итог — 15–22 px, всё жирным, прозрачностью текст не гасить |

Осталось непроверенным: поддерживает ли рантайм модификаторы вроде `@click.stop`
(компилятор их принимает), и каков настоящий потолок размера сообщения — 4288 байт
это то, что понадобилось, а не предел.

Чтобы прогнать экраны без телефона, поставьте `STAGE = 1` в `src/device/stage.js`.

## Установка на браслет

Через AstroBox: страница устройства → карточка быстрых приложений → «+» → выбрать `.rpk`.
Полный порядок установки вместе с сервером и плагином — в [`docs/INSTALL.md`](../docs/INSTALL.md).

Если приложение когда-нибудь подвесит браслет: на зарядке удерживать палец в центре
экрана ~15 с до логотипа MI, либо удалить приложение через AstroBox — по BLE это
работает и при мёртвом тачскрине.
