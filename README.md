# omsu-band-schedule

Расписание пар ОмГУ на экране Xiaomi Smart Band 10.

У браслета нет своего интернета — `@system.fetch` на Xiaomi Vela недоступен, а Wi-Fi там
попросту нет. Единственный канал наружу — `@system.interconnect` через приложение-компаньон
на телефоне. Отсюда три компонента:

```
eservice.omsu.ru ──(раз в 3 ч)──► server/ ──(HTTP + токен)──► astrobox-plugin/ ──(BLE)──► band-app/
```

На iOS приложения не живут в фоне, поэтому синхронизация возможна только когда AstroBox
открыт. Значит, **браслет обязан полностью работать офлайн по кэшу** — это определяющее
ограничение всей архитектуры.

## Зачем отдельный сервер

API вуза отдаёт **1.5 МБ** одним ответом: вся история с сентября 2023 года, 3566 пар,
дни не отсортированы. Плюс названия предметов до 67 символов, `"-"` вместо преподавателя
(189 раз) и `"4-0"` вместо аудитории (233 раза). Всё это надо разобрать один раз на машине
с памятью и нормальной сетью, а на браслет отдать готовое.

Результат — около **4 КБ на две недели**. Влезает в одно interconnect-сообщение: на живом
Band 10 сообщение в 4288 байт дошло одним кадром.

| Компонент | Что это | Статус |
|---|---|---|
| [`server/`](server/) | FastAPI: тянет API вуза, нормализует, отдаёт компактный JSON и ICS | готов |
| [`shared/`](shared/) | Контракт: `schema.json`, `example.json`, `bells.json` | готов |
| [`band-app/`](band-app/) | Vela quick app (`.rpk`), экран 212×520 | работает на устройстве |
| [`astrobox-plugin/`](astrobox-plugin/) | Плагин AstroBox v2: Rust → WebAssembly, пакет `.abp` | работает на устройстве |
| [`reference/`](reference/) | Код старого проекта StudyHelper, только чтение | — |

## Что выяснилось про платформу

Полный журнал — в [`docs/DECISIONS.md`](docs/DECISIONS.md). Коротко о том, чего нет в
русскоязычных источниках:

- **Классический JS-плагин AstroBox мёртв.** Актуален AstroBox v2, где плагины —
  WebAssembly-компоненты (Rust, `wasm32-wasip2`, пакет `.abp`). Загрузчик принимает только
  `api_level` 2 или 3, единица отклоняется. Шаблон JS-плагина заархивирован в октябре 2025,
  документация v1 отдаёт 404.
- **Нарезка данных на части в AstroBox v2 без флоу-контроля приводит к дедлоку**: плагин
  в одном вызове `on_event` забивает очередь BLE, ни разу не возвращая управление хосту.
  Лечится накопительным ACK со скользящим окном. Нам это не понадобилось — нагрузка влезает
  в один кадр.
- **На iOS WASM исполняется интерпретатором** (Pulley64, JIT недоступен). Ещё один довод
  отдавать с сервера готовый JSON, а не обрабатывать данные на телефоне.
- **Словарный эндпоинт групп** (`/schedule/backend/dict/groups`, используется фронтендом вуза)
  стабильно отдаёт 504.

Отдельно — то, что удалось узнать только на живом браслете, ценой одного зависшего
устройства. Правила с указанием источника по каждому пункту: [`docs/VELA-RULES.md`](docs/VELA-RULES.md).

- **`"type": "module"` в `package.json` убивает приложение до первой отрисовки.** Бандлер
  считает модули ES-модулями, а babel-проход тулчейна генерирует для них CommonJS-тело —
  первый же общий модуль бросает `exports is not defined`. Выглядит как чёрный экран,
  тестами на Node не ловится вообще.
- **`<list>` и `<list-item>` не рисуют ничего**, хотя место занимают. Строки — обычные
  `div` с `for`, прокрутка — `<scroll scroll-y="true">` с фиксированной высотой.
- **`width/height: 100%` на корне страницы не разрешается**, размеры задаются в пикселях
  под экран устройства.
- **Снять `console.log` с браслета нечем** — ни AstroBox, ни его CLI, ни плагины этого не
  умеют. Поэтому в приложении есть отладочный экран, а хуки жизненного цикла обёрнуты так,
  чтобы исключение попадало на экран, а не убивало страницу молча.
- **Приложение исполняется в одном потоке с системным интерфейсом** и способно подвесить
  браслет целиком. Помогает удаление приложения по BLE — оно работает и при мёртвом
  тачскрине.

## Быстрый старт

```bash
cd server && uv sync && cp .env.example .env
```

```bash
uv run python -m pytest && uv run ruff check .
```

```bash
docker compose up -d --build
```

```bash
cd band-app && npm install && npm run gen && npm test && npm run build
```

```bash
cd astrobox-plugin && python3 scripts/build_dist.py --release --package
```

Плагин собирается только там, где есть Rust с таргетом `wasm32-wasip2`; на Windows —
в WSL, потому что Smart App Control блокирует `cargo.exe`.

Подробности, переменные окружения и CLI — в [`server/README.md`](server/README.md).
Установка на живые устройства по шагам — [`docs/INSTALL.md`](docs/INSTALL.md).

## Как часто обновляется

| Звено | Когда |
|---|---|
| Сервер ← вуз | раз в 3 часа, сам |
| Телефон ← сервер | в момент запроса от браслета |
| Браслет ← телефон | при каждом открытии приложения |

Инициатор — браслет: quick app должен быть запущен, чтобы принять сообщение, поэтому
фоновой рассылки нет. AstroBox должен быть жив, но не обязан быть открыт — на Android
хватает фона, на iPhone нужен передний план.

Если ничего не изменилось, сервер отвечает `304`, телефон — `up_to_date`, и по Bluetooth
не передаётся ничего.
